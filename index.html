RustDesk three-host mesh

No secrets This page contains no server address, no key, and no peer IDs. setup.sh asks each fresh machine for the real values at run time.

Caution Do not run setup.sh on a host that already has a working RustDesk configuration. It overwrites ~/.config/rustdesk/RustDesk2.toml and /root/.config/rustdesk/RustDesk2.toml. It is intended for fresh machines only.

Pinned version

Channel pre · version 1.2.5

Explainer

Three Linux workstations on a shared LAN, with one host running hbbs and hbbr. RustDesk clients register with the same rendezvous server and share a single Ed25519 key. A widened inbound whitelist allows peers on both the Tailscale CGNAT range and the LAN to connect to each other.

How we got here

1. Audit (read-only)

ps -eo pid,user,args | grep -E '[h]bbs|[h]bbr|[/]rustdesk'
sudo ss -tulpn | grep -E ':2111[4-9]'
sudo ausearch -m avc -ts recent | grep -i rustdesk

2. Upgrade the client on each host

sudo ./upgrade-153-hardened.sh --key-file=rustdesk-server.key

3. Point every host at the same rendezvous

rendezvous_server = '<SERVER>'
relay-server     = '<SERVER>'
api-server       = 'http://<SERVER>:21114'
key              = '<KEY>'
direct-server    = 'Y'
enable-hwcodec   = 'Y'
allow-auto-update = 'N'
whitelist = '100.64.0.0/10,192.168.0.0/16'

4. Verify

rustdesk --version    # expect 1.2.5
rustdesk --get-id     # non-empty means registered
nc -z -w3 <SERVER> 21116

Scripts

setup.sh

Interactive bootstrap for a fresh Fedora/RHEL host. Prompts for the server address and 44-character Ed25519 key.

#!/usr/bin/env bash
# setup.sh - interactive RustDesk bootstrap for a fresh host.
# No server address or key is embedded. Both are asked here.
V="1.2.5"; R="rustdesk-${V}-0.x86_64.rpm"
U="https://github.com/rustdesk/rustdesk/releases/download/${V}/${R}"
y(){ echo "[setup] $*"; }
d(){ y "FAIL: $*"; return 1; }
[ -t 0 ] || d "stdin is not a terminal"
command -v dnf >/dev/null || d "needs dnf"
printf 'Server address: '; read -r S
printf 'Key (44 chars): '; read -r K
[ -z "$S" ] && d "no server"
[ -z "$K" ] && d "no key"
curl -fL -o "/tmp/${R}" "$U" || d "download failed"
[ -s "/tmp/${R}" ] || d "empty file"
sudo dnf install -y "/tmp/${R}" || d "install failed"
rpm -q rustdesk || d "rpm missing"
T=$(printf "rendezvous_server = '%s'\nnat_type = 1\n\n[options]\ncustom-rendezvous-server = '%s'\nrelay-server = '%s'\napi-server = 'http://%s:21114'\nkey = '%s'\ndirect-server = 'Y'\nenable-hwcodec = 'Y'\nallow-auto-update = 'N'\nwhitelist = '100.64.0.0/10,192.168.0.0/16'\n" "$S" "$S" "$S" "$S" "$K")
mkdir -p ~/.config/rustdesk
printf '%s\n' "$T" > ~/.config/rustdesk/RustDesk2.toml
sudo mkdir -p /root/.config/rustdesk
printf '%s\n' "$T" | sudo tee /root/.config/rustdesk/RustDesk2.toml >/dev/null
sudo systemctl enable --now rustdesk.service || d "enable failed"
sudo systemctl restart rustdesk.service || d "restart failed"
sleep 2
y "service: $(systemctl is-active rustdesk)"
y "id: $(rustdesk --get-id)"
y "done"

upgrade-153-hardened.sh (excerpt)

Idempotent upgrade to the pinned version, verifies the RPM, writes the optimised config, restarts the service.

TARGET_VER="1.2.5"
RPM="./rustdesk-${TARGET_VER}-0.x86_64.rpm"
URL="https://github.com/rustdesk/rustdesk/releases/download/${TARGET_VER}/rustdesk-${TARGET_VER}-0.x86_64.rpm"

# validate and install
rpm -qp --nodigest --nosignature "$RPM" >/dev/null 2>&1
dnf install -y "$RPM"

# restart
sudo systemctl enable --now rustdesk.service
sudo systemctl restart rustdesk.service

Fresh machine bootstrap

On a new host:

curl -fsSL https://swipswaps.github.io/rustdesk-mesh-notes/setup.sh -o setup.sh
bash setup.sh

Two questions are asked:

  1. Server address — the host running hbbs.
  2. Server public key — the 44-character Ed25519 key.

Caution: permanent password setup.sh does not set a permanent password. If the fresh host needs unattended access, set one in the RustDesk GUI under Settings → Security, and enable TOTP 2FA while there. Do not place a password in RustDesk2.toml by hand.

Warning: inbound exposure The whitelist 100.64.0.0/10,192.168.0.0/16 permits any peer on the Tailscale CGNAT range or the LAN. Narrow it to specific /32 addresses if the mesh is not a trusted network.
